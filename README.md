# VPN subscription checker

Источники включают ежедневно обновляемые большие списки `Hidashimora/free-vpn-anti-rkn`, агрегаторы GitVerse (`kort0881`, `Bazz1024`, `Pizduk`) и мелкие живые подписки — полный список в [`sources.txt`](sources.txt). Суммарный пул > 50 000 уникальных узлов.

Скрипт каждый час скачивает источники, проверяет прокси через Xray-core из GitHub Actions и публикует список отвечающих узлов в формате URI, который понимает v2rayN.

> Используй только узлы и сервисы, которыми разрешено пользоваться в твоей юрисдикции. Публичные бесплатные узлы нестабильны и могут быть небезопасны.

## 1. Создание репозитория

1. Создай **публичный** репозиторий на GitHub, например `vpn-sub-checker`.
2. В локальной папке проекта выполни:

```bat
git init
git add .
git commit -m "initial vpn checker"
git branch -M main
git remote add origin https://github.com/ТВОЙ_ЛОГИН/vpn-sub-checker.git
git push -u origin main
```

Публичный репозиторий нужен, чтобы GitHub Actions не упирался в небольшой лимит минут приватного аккаунта. Не добавляй в него личные ключи, токены или приватные подписки.

## 2. Запуск

Открой GitHub → вкладка **Actions** → workflow **Check VPN subscription** → **Run workflow**. В дальнейшем cron запускает его примерно раз в час (GitHub может задерживать cron на несколько минут).

> **Важно про cron:** расписание срабатывает только из **ветки по умолчанию** репозитория.
> Если ветка по умолчанию — не та, где лежит [`check.yml`](.github/workflows/check.yml)
> (например `master`, а проект в `main`), ежечасовые запуски молча не выполняются.
> Проверка: Settings → Branches → default branch должен совпадать с веткой проекта
> (в API: `default_branch` в информации о репозитории).

В workflow используется официальный Xray-core. Каждый узел проверяется через локальный SOCKS5-вход двумя раундами по трём российским endpoint-ам: `avito.ru`, `vk.com` и `rutube.ru`. Каждый запрос должен вернуть `HTTP 200` и загрузить тело страницы не менее 1000 байт. Узел публикуется только если успешно прошёл минимум 3 из 6 проверок — это отсекает полностью нерабочие прокси, но при этом захватывает живые «пограничные» узлы, которые могут мигнуть только в части запросов. Проверка выполняется из IP-адресов GitHub Actions, а не из твоей домашней сети; это проверка доступности российских платформ, но не полноценная проверка именно из российского IP.

Так как пул вырос до десятков тысяч узлов, ежечасно проверяется не всё: берутся все узлы из предыдущего результата [`sub.txt`](output/sub.txt) (чтобы проверенные узлы не выпадали из подписки) и случайная выборка свежих кандидатов до лимита `--limit` из [`check.yml`](.github/workflows/check.yml) (сейчас 6000). За несколько прогонов весь пул оказывается просмотрен; полный охват одного прогона при 64 воркерах занял бы часы и упёрся бы в лимиты GitHub Actions. Если в v2rayN узлов меньше, чем хотелось бы, — подними `--limit` и/или `--workers` в [`check.yml`](.github/workflows/check.yml): больше узлов за прогон = больше рабочих в подписке.

## 3. Подписка в v2rayN

После первого успешного запуска итоговая ссылка будет:

```text
https://raw.githubusercontent.com/ТВОЙ_ЛОГИН/vpn-sub-checker/main/output/sub.txt
```

В v2rayN:

1. Открой **Подписки** → **Настройки подписки**.
2. Добавь URL выше и задай любое имя.
3. Нажми **Обновить подписки**.
4. В настройках подписки включи автоматическое обновление, если доступная версия v2rayN это поддерживает.

Важно: Xray проверяет только поддержанные схемы `vmess://`, `vless://`, `trojan://` и `ss://`. Неподдержанные форматы будут пропущены.

## Локальный запуск

Нужны Python 3.10+, Xray-core и `curl` в `PATH`:

```bat
python scripts\check.py --xray C:\путь\к\xray.exe --limit 20 --workers 4 --timeout 10
```

В Windows-папке v2rayN обычно уже есть `xray.exe`; укажи полный путь к нему. Локальный запуск проверяет узлы из твоей сети и пишет результаты в `output\sub.txt` и `output\report.md`.

## Обновление подписки

`output/sub.txt` перезаписывается на каждом прогоне результатами текущей проверки — устаревшие узлы не «зависают» в подписке. Если какой-то узел перестал отвечать, он автоматически исчезнет при следующем обновлении. Стабильность узлов поддерживается приоритетной выборкой: проверенные ранее рабочие узлы всегда перепроверяются и сохраняются.

## Файлы

- [`sources.txt`](sources.txt) — исходные URL подписок.
- [`scripts/parsers.py`](scripts/parsers.py) — извлечение URI и создание Xray outbound-конфигураций.
- [`scripts/check.py`](scripts/check.py) — проверка узлов и публикация результатов.
- [`.github/workflows/check.yml`](.github/workflows/check.yml) — ежечасный запуск.
- [`output/sub.txt`](output/sub.txt) — итоговая подписка.
- [`output/report.md`](output/report.md) — отчёт проверки.
