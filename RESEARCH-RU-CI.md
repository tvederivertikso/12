# Исследование: замена GitHub Actions для проверки из России

Дата: 2026-09-06. Причина: GitHub Actions выполняется на IP GitHub (не из России),
поэтому результат проверки узлов не совпадает с реальной работоспособностью у
российского пользователя. Домашний ПК не подходит (должен быть включён постоянно,
полный прогон 1582 узлов занимает 40–90 минут).

## Главная находка: GitFlic (gitflic.ru)

Российская платформа разработки (SaaS, сервера в России). Проверено по странице
тарифов https://gitflic.ru/price:

**Бесплатный тариф SaaS — 0 ₽/мес, включает:**
- Базовый функционал Git
- **CI/CD** (конвейеры, задачи)
- Реестр контейнеров и пакетов
- Публичные репозитории — безлимит пользователей
- API/Webhooks, Git LFS

**Разделы CI/CD в документации** (видны в навигации https://gitflic.ru/help):
- Общая информация, Задача, Конвейер
- Агенты CI/CD (типы: Shell, PowerShell, Docker, Kubernetes)
- Справочник .yaml файла — формат конфигурации похож на GitLab CI
- **Планировщик конвейеров** — аналог cron, нужен для ежечасного запуска
- Примеры использования, Шаблоны конфигураций
- Кэш, SAST/DAST/SCA, Unit-тесты

### Критический открытый вопрос

Не удалось подтвердить из открытой документации (она SPA, рендерится в браузере):
есть ли у GitFlic **общие облачные агенты** (shared runners), или агент нужно
устанавливать самому (Shell/PowerShell/Docker) на свою машину.

Проверить после регистрации: Проект → Настройки → Настройка CI/CD → Агенты CI/CD.

- Если общие агенты есть → задача решается полностью бесплатно и из России:
  конвертировать [`check.yml`](.github/workflows/check.yml) в gitflic-ci.yaml,
  включить планировщик, забрать raw-ссылку результата.
- Если общих агентов нет → нужен свой агент, и вопрос сводится к «где его держать»
  (круг замыкается: снова нужен VPS/ПК).

Поиск через Яндекс (r.jina.ai) + прямые заходы на страницы проектов. Итог:

| vault/v2ray-core | Зеркало github.com/v2fly/v2ray-core | Нет — исходники ядра |

| sergey4321kotov/novyi-vpn-2025-dlya-vseh | Пустой README-шаблон GitFlic | Нет |
| red-stars-systems/red-star-vpn | Репозиторий полностью пустой | Нет |
| jno/ovpnctl, denischopyk/wireguard-keenetic и др. | Утилиты для настройки своих VPN | Нет |

**Вывод: публичных подписок с готовыми узлами на GitFlic НЕТ.** Все найденные
репозитории — либо зеркала клиентов/ядер, либо инструменты для настройки
собственного сервера. Публичный каталог проектов по запросам vpn/proxy/vless/
v2ray/xray/подписка ничего не выдаёт. Это значит: подписки придётся тянуть
из тех же внешних источников ([`sources.txt`](sources.txt)), а GitFlic
рассматривать только как площадку для CI/CD-проверки.

### Что уже готово для переноса

- Скрипт проверки [`scripts/check.py`](scripts/check.py) — чистый Python 3 + curl + xray,
  не зависит от GitHub вообще.
- Источники в [`sources.txt`](sources.txt).
- Публикация результата — обычная запись файлов в [`output/sub.txt`](output/sub.txt).

## Альтернатива: Amvera Cloud (amvera.ru)

Российский PaaS, проверено доступность главной страницы (HTTP 200).

- Регионы: **Москва**, Варшава, Майами — можно выбрать российский регион.
- Деплой через `git push` или интерфейс, поддержка Python и Docker из коробки.
- Подходит для долгоживущего приложения: можно развернуть демон, который сам раз в
  час запускает [`check.py`](scripts/check.py) и отдаёт `sub.txt` по HTTP — тогда
  GitHub для публикации вообще не нужен, v2rayN подписывается на URL приложения.
- Минус: тарифы скрыты за авторизацией/защитой (403), бесплатный пробный период
  ограничен, постоянное приложение с проверкой ~1600 узлов — это CPU-нагрузка,
  скорее всего уйдёт в платный тариф (порядка нескольких сотен руб/мес).

## Прочие проверенные варианты

| Сервис | Статус | Вывод |
|---|---|---|
| GitVerse | HTTP 200 | Публичной документации CI/CD не найдено |
| GitFlic | HTTP 200 | CI/CD в бесплатном тарифе, есть планировщик |
| Timeweb Cloud | HTTP 200 | VPS от ~200 ₽/мес, регион СПб/Москва |
| VK Cloud | HTTP 200 | VPS, есть пробные кредиты |
| REG.RU / FirstVDS / RuVDS / Beget | HTTP 200 | Дешёвые VPS от ~150–300 ₽/мес |
| Drone CI / Woodpecker CI | HTTP 200 | Свои runner-ы, облако платное |
| Azure DevOps | HTTP 200 | Бесплатные минуты, но не Россия |

## Рекомендуемый порядок действий

1. Зарегистрироваться на GitFlic (бесплатно).
2. Проверить наличие общих агентов CI/CD в настройках проекта.
3. Если есть — перенести репозиторий, конвертировать workflow в gitflic-ci.yaml,
   включить планировщик (ежечасно), убедиться, что агент в РФ (сделать в конвейере
   `curl ifconfig.me` или `curl ipinfo.io/country` и записать в отчёт).
4. Если общих агентов нет — выбрать: Amvera (Москва, PaaS, просто) или дешёвый
   российский VPS (Timeweb/FirstVDS, полная свобода, cron + xray).
5. GitHub можно оставить зеркалом результата для v2rayN, либо отказаться от него.

Временные скрипты исследования удалены после фиксации результатов в этом файле.
