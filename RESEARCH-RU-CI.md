# Исследование: замена GitHub Actions для проверки из России

Дата: 2026-09-06. Причина: GitHub Actions выполняется на IP GitHub (не из России),
поэтому результат проверки узлов не совпадает с реальной работоспособностью у
российского пользователя. Домашний ПК не подходит (должен быть включён постоянно,
полный прогон 1582 узлов занимает 40–90 минут).

## ЛУЧШИЙ КАНДИДАТ: GitVerse (gitverse.ru) — обновление 2026-09-06

Российская платформа (сервис «СберТеха» Giga). Проверено напрямую, анонимно,
без регистрации. Ключевые факты из официальной документации:

**CI/CD (совместим с GitHub Actions!):**
- Синтаксис workflow — **практически идентичен GitHub Actions** (официальный FAQ:
  «Синтаксис YAML-файлов CI/CD в GitVerse в целом совместим с GitHub Actions.
  Вы можете использовать существующие workflow практически без изменений»).
- **Облачные раннеры есть и бесплатны**: лимит 1000 минут/мес на публичные
  репозитории (500 мин — приватные; верифицированные организации: 2000/1000).
- **Максимальная длительность одной задачи — 15 минут** (потом принудительное
  прерывание). Наш полный прогон 1582 узлов на 40 воркерах занимает ~9 минут —
  вписывается, но впритык; при росте числа узлов дробить прогон на части
  (needs: / несколько задач) или резать лимитом --limit.
- Зеркальным (импортированным) репозиториям CI/CD **недоступен** — репозиторий
  нужно создавать/пушить напрямую, не через зеркало.
- Раннер: act_runner (Gitea-совместимый), self-hosted опционально.

**GitVerse Pages — публикация результата по чистому URL:**
- Сайт проекта: `https://<owner>.gitverse.site/<repo-name>`
- Требования: репозиторий публичный, CI/CD включён, ветка любая (можно pages),
  папка на выбор: /, /docs, /site, /public, /out.
- Идеально для подписки: кладём `sub.txt` в ветку → v2rayN подписывается на
  `https://<owner>.gitverse.site/<repo>/sub.txt` — без raw.githubusercontent,
  который может блокироваться.

**Плюс: на GitVerse есть живые прокси-подписки (в отличие от GitFlic):**
- `Bazz1024/vpn-configs-mirror` — зеркало GitHub-репо, синк каждые ~30 мин,
  файл `Vless-Reality-White-Lists-Rus-Mobile.txt`: ~195 vless + 204 ss.
- `kort0881/vpn-aggregator` — агрегатор с out/subs/: `vmess_sub.txt`
  (16011 vmess + 16011 ss), `ss_sub.txt` (22302 ss), `eu_sub_1..6.txt`.
- `kort0881/vpn-vless-configs-russia` — 1.68 GiB, автообновление ежедневно.
- `Ayub/vpn-configs-for-russia` — BLACK_VLESS_RUS.txt: 399 vless + 399 ss.
- `Lonnory/VlessALL` — Vpn.txt: 132 vless + 138 ss + 3 trojan.
- Доступ к файлам анонимный: `https://gitverse.ru/<owner>/<repo>/content/<branch>/<path>`
  (HTML-обёртка, ключи внутри; для парсинга нужна очистка от тегов и
  `\u0026` → `&`).

**Вывод: GitVerse закрывает ВСЕ потребности проекта:**
1. CI/CD из России (облачные раннеры, синтаксис GitHub Actions) — проверка узлов.
2. Публикация подписки по чистому URL (Pages) — для v2rayN.
3. Дополнительные источники подписок прямо на платформе.

### План миграции на GitVerse
1. Зарегистрироваться на gitverse.ru (бесплатно).
2. Создать репозиторий (НЕ зеркало!) и запушить текущий проект.
3. Включить CI/CD: Настройки → Репозиторий → тумблер CI/CD.
4. Положить [`check.yml`](.github/workflows/check.yml) — синтаксис совместим;
   проверить, что cron-триггер срабатывает (в GitVerse есть запуск по расписанию).
5. В workflow добавить шаг `curl ifconfig.me` — убедиться, что раннер из РФ.
6. Включить Pages: Настройки → Страницы → ветка main, папка /output.
7. Сменить подписку в v2rayN на `https://<owner>.gitverse.site/<repo>/sub.txt`.
8. Следить за лимитом: 1000 мин/мес; ежечасный запуск по ~10 мин = ~7200 мин/мес —
   ПРЕВЫШАЕТ лимит! Нужно: запуск раз в 2–3 часа, либо сократить время прогона
   (меньше узлов через --limit), либо self-hosted runner.

**ВАЖНО про лимиты:** ежечасный прогон не влезает в 1000 мин/мес. Варианты:
- раз в 3 часа (8 прогонов/сутки × 10 мин = 2400 мин/мес) — всё ещё много;
- раз в 6 часов (4 × 10 = 1200 мин/мес) — близко к лимиту;
- раз в 8 часов (3 × 10 = 900 мин/мес) — влезает;
- или сократить прогон до ~5 минут (--limit 800, воркеров больше) и раз в 4 часа.

## Запасной вариант: GitFlic (gitflic.ru)

Российская платформа разработки (SaaS, сервера в России). Проверено по странице
тарифов https://gitflic.ru/price:

**Бесплатный тариф SaaS — 0 ₽/мес, включает:**
- Базовый функционал Git
- **CI/CD** (конвейеры, задачи)
- Реестр контейнеров и пакетов
- Публичные репозитории — безлимит пользователей
- API/Webhooks, Git LFS

**Разделы CI/CD в документации** (видны в навигации https://gitflic.ru/help):
- Общая информация, Задача, Конвейер
- Агенты CI/CD (типы: Shell, PowerShell, Docker, Kubernetes)
- Справочник .yaml файла — формат конфигурации похож на GitLab CI
- **Планировщик конвейеров** — аналог cron, нужен для ежечасного запуска
- Примеры использования, Шаблоны конфигураций
- Кэш, SAST/DAST/SCA, Unit-тесты

### Критический открытый вопрос

Не удалось подтвердить из открытой документации (она SPA, рендерится в браузере):
есть ли у GitFlic **общие облачные агенты** (shared runners), или агент нужно
устанавливать самому (Shell/PowerShell/Docker) на свою машину.

Проверить после регистрации: Проект → Настройки → Настройка CI/CD → Агенты CI/CD.

- Если общие агенты есть → задача решается полностью бесплатно и из России:
  конвертировать [`check.yml`](.github/workflows/check.yml) в gitflic-ci.yaml,
  включить планировщик, забрать raw-ссылку результата.
- Если общих агентов нет → нужен свой агент, и вопрос сводится к «где его держать»
  (круг замыкается: снова нужен VPS/ПК).

**Вывод: публичных подписок с готовыми узлами на GitFlic НЕТ.** Все найденные
репозитории — либо зеркала клиентов/ядер, либо инструменты для настройки
собственного сервера. Публичный каталог проектов по запросам vpn/proxy/vless/
v2ray/xray/подписка ничего не выдаёт. Это значит: подписки придётся тянуть
из тех же внешних источников ([`sources.txt`](sources.txt)), а GitFlic
рассматривать только как площадку для CI/CD-проверки.

## Альтернатива: Amvera Cloud (amvera.ru)

Российский PaaS, проверено доступность главной страницы (HTTP 200).

- Регионы: **Москва**, Варшава, Майами — можно выбрать российский регион.
- Деплой через `git push` или интерфейс, поддержка Python и Docker из коробки.
- Подходит для долгоживущего приложения: можно развернуть демон, который сам раз в
  час запускает [`check.py`](scripts/check.py) и отдаёт `sub.txt` по HTTP — тогда
  GitHub для публикации вообще не нужен, v2rayN подписывается на URL приложения.
- Минус: тарифы скрыты за авторизацией/защитой (403), бесплатный пробный период
  ограничен, постоянное приложение с проверкой ~1600 узлов — это CPU-нагрузка,
  скорее всего уйдёт в платный тариф (порядка нескольких сотен руб/мес).

## Рекомендуемый порядок действий (обновлено после аудита GitVerse)

1. **GitVerse — основной путь**: регистрация → создание репозитория (не зеркало!)
   → включить CI/CD → пушить [`check.yml`](.github/workflows/check.yml)
   (синтаксис совместим с GitHub Actions) → проверить IP раннера (`curl ifconfig.me`)
   → включить Pages для публикации sub.txt по чистому URL.
2. Учесть лимит 1000 мин/мес: запускать проверку раз в 6–8 часов или сократить
   прогон (--limit). Ежечасный запуск не влезает в бесплатный лимит.
3. Дополнительно: добавить GitVerse-репозитории (Bazz1024, kort0881, Ayub,
   Lonnory) в [`sources.txt`](sources.txt) как источники подписок — они уже
   доступны из РФ без блокировок.
4. GitFlic — запасной вариант (CI/CD есть в бесплатном тарифе, но публичных
   подписок на платформе нет, агенты не подтверждены).
5. Amvera / дешёвый VPS — если лимитов GitVerse не хватит.
6. GitHub остаётся зеркалом результата (raw-ссылка) до полного переезда.

Временные скрипты исследования удалены после фиксации результатов в этом файле.
